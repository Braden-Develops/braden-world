Admin guide

Permissions, server management, allowlists and rollbacks for the braden.world network. Everything here works from in-game chat.

Overview

The network is a Velocity proxy in front of several Paper servers. A custom proxy plugin, Omniscense, creates and manages those servers on demand. Every server runs the same set of plugins:

PluginRuns onPurpose
OmniscenseProxyCreate, start, stop and remove servers; per-server allowlists
LuckPermsProxy and every serverPermissions, shared across the whole network
CoreProtectEvery serverBlock and container logging, lookups and rollbacks
ViaVersionEvery serverLets newer clients (26.3) join the 26.2 servers

Paper's built-in anti-xray is also enabled on every server.

LuckPerms

LuckPerms decides who can run which commands. All servers and the proxy share one permission database, so a group or player change applies network-wide and syncs to every server automatically.

Two commands, same data

CommandUse it for
/lpv …The proxy. Works from any server. Use it for proxy permissions like omniscense.*.
/lp …The Paper server you're on. Same data, plus tab completion for that server's commands.

The web editor (easiest)

/lpv editor

Click the link it prints, edit groups and players in your browser, then press Save and run the /lpv applyedits … command it gives you.

Groups

Grant permissions to groups, then put players in groups. Everyone starts in default, which has no extra permissions.

# create a moderator group
/lpv creategroup mod
/lpv group mod permission set minecraft.command.tp true
/lpv group mod permission set minecraft.command.gamemode true
/lpv group mod permission set coreprotect.inspect true
/lpv group mod permission set coreprotect.lookup true

# put a player in it (and take them out again)
/lpv user CherrieBara parent add mod
/lpv user CherrieBara parent remove mod

Single players

/lpv user <player> permission set <node> true
/lpv user <player> permission unset <node>
/lpv user <player> info                            # groups and permissions
/lpv user <player> permission check <node>        # why they do or don't have it

Only on one server

Add server=<name> to limit a permission to one server, using the same name as /server:

/lpv group builder permission set minecraft.command.gamemode true server=creative

Leave proxy permissions (omniscense.*) global, without a server= context. The proxy checks them under its own name, not the server the player is on.

Be careful with *. It grants every permission on every server, including LuckPerms itself and server management. Give other admins a group with only what they need.

Managing servers

/omni is short for /omniscense. All of these need omniscense.admin.

CommandWhat it does
/omni create <name>Create a new server with its own world, start it and add it to the network. Join it with /server <name>. Names are 1–32 lowercase letters, digits or dashes.
/omni listEvery server, its status, and how many are running out of the limit
/omni stop <name>Stop a server (it saves first). It stays stopped across restarts until you start it.
/omni start <name>Start a stopped server
/omni remove <name>Remove a server and its allowlist. Its world is kept on disk.

Running-server limit. The host can run a limited number of servers at once, worked out from its CPU and memory (currently 3). /omni create and /omni start refuse to go over it. Stop a server to make room.

The main server (baseline-minecraft-server) is created automatically and is where players land when they join.

Allowlists

Each server has its own optional allowlist. Every allowlist is off until you turn it on, so new servers are open to everyone.

/omni allowlist <server> add <player>      # Java username; works before their first join
/omni allowlist <server> remove <player>
/omni allowlist <server> list
/omni allowlist <server> on                # admins only
/omni allowlist <server> off               # admins only
  • Entries follow the Minecraft account, so name changes don't matter.
  • Turning a list on doesn't kick players already on that server.
  • Give a trusted player omniscense.allowlist to let them add and remove people without being able to switch lists off.
  • Anyone with omniscense.allowlist.bypass (or *) can always get in, so you can't lock yourself out.

CoreProtect

CoreProtect records block changes, container transactions, kills and more on every server. Use it to find out who did something and undo it.

CommandWhat it does
/co iToggle inspect mode. Left-click a block for its history, right-click a chest for its transactions.
/co lookup u:<player> t:1hEverything a player did in the last hour
/co lookup u:<player> t:1d a:-block i:diamond_oreDiamond ore a player broke in the last day (good for spotting x-ray)
/co rollback u:<player> t:2h r:50Undo a player's changes from the last 2 hours within 50 blocks of you
/co restore u:<player> t:2h r:50Reverse that rollback
/co purge t:30dDelete log data older than 30 days to keep the database small (needs coreprotect.purge; purging anything newer than 30 days must be done from the console)

Common parameters: u: user, t: time (30m, 2h, 3d), r: radius in blocks or #global, a: action (block, +block, -block, container, kill), i: block or item. Each server has its own log.

Server defaults

Every server created with /omni create starts with these settings:

SettingDefault
Minecraft version26.2 (Paper), joinable by 26.2 and 26.3 clients
Max players20 per server
View / simulation distance8 / 6 chunks
Memory2 GB heap, 2 CPU cores
Anti-xrayOn (engine mode 2): overworld ores, chests, mineshafts, geodes and nether ores below y=64
Message of the dayThe server's name
AllowlistOff

The 26.2 version is temporary: CoreProtect doesn't support 26.3 yet. When it does, servers can be upgraded in place; worlds upgrade forward but can't go back.

How it works

  • Containers. Everything runs in Podman containers on one host. The proxy plugin talks to Podman to create and manage the Paper servers.
  • Isolation. Each Paper server has its own network shared only with the proxy, so servers can't reach each other. Only the proxy is reachable from the internet.
  • One database. MongoDB holds the server list, permissions and allowlists, with a separate login per component.
  • Persistent. Worlds, the database and secrets survive restarts, updates and reboots. The network starts itself when the host boots.
  • Address. braden.world follows the host's IP automatically, and a DNS SRV record means players don't need a port.

Operations

These run on the host, from the Omniscense repository.

TaskHow
Deploy or updatescripts/deploy.sh. Rebuilds the plugin and restarts the proxy (players reconnect in about 20 seconds). Worlds and data are kept.
Proxy console commandscripts/console.sh "<command>", e.g. scripts/console.sh "lpv user Steve info"
Stop or start everythingsudo systemctl stop omniscense / start / status. Servers save before stopping.
Remove the deploymentscripts/cleanup.sh keeps all data. --purge deletes every world and the database.
BackupsNightly at 04:00 to a separate machine: every world, the database and secrets. Kept for 14 days.
RestoreSteps are at the top of scripts/backup.sh: stop the server with /omni stop, restore its archive into its volume, start it again.

For "undo what one player did", use CoreProtect. Backups are for losing a whole world or the database.
